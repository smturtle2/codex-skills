# user-dialog

입력 필드와 Markdown 문서, 이미지 또는 문서 파일 경로를 자유롭게 조합해 팝업을 만들고 응답을 원래 Codex 작업에 사용자 메시지로 전달합니다.

[전체 스킬](../../README.ko.md#skills) · [English](user-dialog.md)

## 설치

```text
Use $skill-installer to install skills/user-dialog from https://github.com/smturtle2/codex-skills.
```

## 런타임 요구 사항

런처는 uv로 Python 의존성을 관리합니다. Markdown과 독립 코드 블록을 사용하려면 네이티브 WebKitGTK 6.0 런타임도 필요합니다.
Debian/Ubuntu에서는 GTK 및 libadwaita 런타임 패키지와 함께 `gir1.2-webkit-6.0`을 설치하세요.

기존 관리형 공유 데몬에 연결된 CLI 작업과 로컬 데스크탑 작업에 응답을 전달합니다.
CLI는 `codex app-server daemon version`에서 `socketPath`를 얻고, 원래 작업이
그 서버에 로드되어 있는지 확인한 뒤 같은 작업에 연결해 네이티브 항목 알림을 받습니다.
데스크탑은 `$CODEX_HOME/ipc/ipc.sock`에서 정확한 작업 소유자와 정식 로그 경로를 찾습니다.
`CODEX_HOME`의 기본값은 `~/.codex`입니다. 연결은 초안과 함께 저장하고 자동으로 검증합니다.
엔드포인트를 수동으로 지정하거나 앱 실행 설정을 바꾸거나 새 서버를 실행할 필요가 없습니다.
원격 서버와 CLI 내장 서버는 지원하지 않습니다. 스킬 런처의 `doctor --delivery` 명령으로
응답을 전달하지 않고 네이티브 연결 탐색과 도착 확인의 전제 조건을 검사할 수 있습니다.

상태와 응답 형식은 공유하며, 네이티브 연결·전송·도착 확인·복구는 각 클라이언트의
경로에서 처리합니다. CLI 팝업은 분리된 프로세스로 유지하며 Core의 `turn/start`를
사용합니다. 데스크탑은 팝업에서 입력을 받는 동안 원래 턴을 유지하고 소유자의
네이티브 steering 경로만 사용합니다. 에이전트는 같은 실행 세션이나 셀을 짧은
간격으로 기다리며, 입력 가능한 팝업이 열려 있는 동안 최종 응답을 보내지 않습니다.
렌더러를 별도 프로세스로 실행하는 것만으로는 턴이 유지되지 않습니다.
취소하면 입력 가능한 팝업을 닫고 초안이나 저장된 답변을 보존합니다.
데스크탑에는 새 턴을 시작하는 fallback이 없습니다.

제출 후에는 데스크탑 팝업의 입력을 잠그고, 입력 수락 응답을 받거나 전송 시도의 결과가
불명확해지면 정식 로그 확인 전에 런처를 반환합니다. 렌더러는 별도로 도착을 확인합니다.
저장한 UUID와 정확한 원문이 CLI의 `item/completed` 알림 또는 데스크탑 소유자 로그의
완료된 `UserMessage`에 나타나야 팝업을 자동으로 닫습니다. 전송 이후 오류가 나거나
서버 응답을 잃어도 다시 보내지 않으며, 복구는 해당 클라이언트의 저장된 네이티브 기록을
확인합니다. 입력 가능한 데스크탑 팝업은 원래 턴이 정상 종료된 뒤까지 유지할 수 없습니다.
네이티브 사용자 메시지 UUID가 없는 레거시 로그로는 불명확한 전달을 확인할 수 없습니다.

응답의 제목·항목명·누른 버튼에는 CLI 테마의 강조색이 자동 적용됩니다.
기존 팝업 JSON을 그대로 사용하며, 강조 범위나 추가 스타일 옵션을 지정할 필요가 없습니다.
사용자가 직접 쓴 Markdown을 포함해 답변 원문은 유지합니다. 다른 클라이언트에서는 일반 텍스트로
표시될 수 있습니다. 새 제출은 `message.txt`에 텍스트 미리보기를, `state.json`에 전체 메시지를 저장합니다.

## 사용법

예를 들어 “$user-dialog를 사용해 배포 대상을 물어보고 staging과 production 버튼을 보여줘”라고 요청할 수 있습니다.

작성한 콘텐츠에는 문자열 `text` 또는 입력/선택 값의 `ref`를 받는 `markdown` 노드를 사용하세요. Markdown 파일은 `file`에서 같은 렌더러를 사용하며, 제목·테두리·원문 복사·코드 복사 컨트롤을 `display` 옵션으로 각각 설정할 수 있습니다.

본문과 입력·버튼에는 포함된 Pretendard, 코드에는 D2Coding을 사용합니다. 독립 코드와 Markdown 안의 코드 블록은 구문 색상·여백·상단 바를 공유하며, 언어명은 왼쪽, 줄 바꿈 및 복사 컨트롤은 오른쪽에 표시합니다. 줄 바꿈은 기본으로 켜져 있고 끄면 가로 스크롤을 사용하며, 복사는 원본 텍스트를 그대로 보존합니다. Markdown 파일은 기본적으로 파일명과 문서 테두리를 유지합니다. 글꼴은 로컬에서 불러오며 시스템 테마나 설치된 글꼴을 변경하지 않습니다.

## 작업 파일

대화 실행에 지속 상태가 필요하면 사용자가 위치를 지정하지 않은 경우 프로젝트 루트 기준 `.codex-skills/user-dialog/<run-id>/`를 사용합니다. 기존 위치는 옮기지 않고 그 자리에서 재개하며, 복구에 필요한 상태는 보존하고 이번 실행에서 만든 폐기 가능한 중간 파일만 정리합니다.

리터럴 `ref` 값은 제자리에서 갱신됩니다. 문서 텍스트를 선택하거나 드래그하는 동안 실시간 대체를 미루고, 선택 중에는 자동 크기 조정도 미룹니다. 초안 갱신은 300ms 동안 합쳐지며 제출 또는 닫기 전에 반영됩니다.

숫자·날짜 입력은 미완성 값과 잘못된 값도 재개와 호환되는 갱신을 위해 그대로 보존합니다. 제출하면 초안을 저장하고 활성 항목을 변환·검증한 뒤, 응답을 기록하고 전달합니다. 무한대와 NaN을 포함한 잘못된 숫자는 항목 오류로 표시하며 텍스트 답변은 원문 그대로 유지합니다. 제출된 숫자·날짜는 정규화된 값을 사용하고 정수의 정확도를 보존합니다.
조건을 제어하는 입력은 제어 대상 바깥에 두세요. 조건이 자기 입력이나 하위 입력에 의존하거나 항목 간 의존성이 순환하면 요청을 거부합니다. 잘못된 필수 입력이 스스로 편집을 막거나 제출에서 빠지는 것을 방지합니다.

탭·페이지는 지정한 `none`, `crossfade`, `slide`, `fade-through` 효과와 시간을 따릅니다. 한 표시 제어기가 문서 준비와 레이아웃 안정을 기다리고 효과를 적용한 뒤 초점을 복원합니다. 시간이 0이면 애니메이션을 생략하되 준비 확인은 유지합니다.
